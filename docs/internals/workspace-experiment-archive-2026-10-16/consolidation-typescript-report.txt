Selection and fail-closed behavior
Both additional Nx targets use the existing @nrwl/jest:jest executor and Jest config.
Their shared exact positive regex is:
libs/system/workspace/adapters-json-tests/src/lib/(database/security/response-context|protocol/read-contract)\.spec\.ts$
Pure sets testPathPattern to that regex; integration sets testPathIgnorePatterns to
that same regex. Both set passWithNoTests:false and have distinct coverage outputs.
A newly added unrelated spec defaults to integration; neither a directory allowlist
nor title filter can silently omit it. Pure plus integration is disjoint and exhaustive.
Default test has no filter. @nrwl/jest getJestProjects deduplicates configs by Set,
so root Jest project discovery still includes this project once despite three targets.
Named targets are deliberate: pinned Nx 14.8.9 silently discards unknown configuration
names in create-task-graph.js:109–114. We therefore do not recommend Nx configurations
or an environment toggle. Unknown target names fail target resolution; zero matching
files fail the new targets. The exact generated selections still require validation
because config spelling errors can otherwise broaden one partition.
