Small target design

Illustrative concrete implementation:
    private Target DotnetCoreWorkspacePureTest => _ => _
        .DependsOn(DotnetCoreGenerate)
        .Executes(() =>
        {
            foreach (var suite in new[]
            {
                (Project: Paths.DotnetCoreWorkspaceTestsLocal, Name: "DotnetCoreWorkspaceLocalPure"),
                (Project: Paths.DotnetCoreWorkspaceTestsRemoteJsonSystemText, Name: "DotnetCoreWorkspaceSystemTextPure"),
                (Project: Paths.DotnetCoreWorkspaceTestsRemoteNewtonsoftSharp, Name: "DotnetCoreWorkspaceNewtonsoftPure"),
            })
            {
                DotNetTest(s => s.SetProjectFile(suite.Project)
                    .SetFilter("Category=Pure")
                    .AddLoggers($"trx;LogFileName={suite.Name}.trx")
                    .SetResultsDirectory(Paths.ArtifactsTests));
            }
        });

    private Target CiDotnetCoreWorkspacePureTest => _ => _
        .DependsOn(DotnetCoreWorkspacePureTest);

Tradeoff and recommendation
Recommend the two-new-target design and method-level traits. It removes a 124-name runtime filter and avoids repeating 724 pure rows across two-provider validation while keeping codec and provider boundaries explicit. Relative to naively rerunning all three assemblies per provider, the two-provider plan saves exactly 724 redundant pure executions, not meaningful codec/provider coverage. It also removes all 28 unnecessary live Profile setups for those mock rows across two providers (seven rows × two codecs × two providers); fourteen actual codec/method rows still run once.
The cost is 124 annotations and a documented meaning change for three direct Nuke target names. The aggregate and unfiltered dotnet test remain complete. An alternative that preserved every direct target as an all-tests umbrella would need separate integration-only wrappers or a skip parameter; it adds scheduling indirection solely to retain those names' old meaning. A class trait or prefix filter is smaller syntactically but incorrectly classifies inherited integration tests. A separate test project would remove fixture concerns structurally but adds package/project/build ownership without a need in this bounded work.
