Hypothetical removal of the .NET workspace Local adapter — current-source analysis, 2026-10-16

Recommendation
Removing it is coherent if applications do not need an in-process workspace/Session connection directly over a borrowed SQL IDatabase. The remaining supported workspace boundary would be HTTP, using System.Text.Json or Newtonsoft in .NET and the existing TypeScript HTTP implementation. SQL database adapters, server executors and database/domain APIs remain. There are no in-repository production consumers of the Local workspace adapter; external application usage is unknown. This is a separate supported-feature decision, not permission to delete tests under the completed consolidation map.

Measured production scope
The adapter has four C# source files, 292 physical lines total, plus its project file:
- DatabaseConnection (56 lines): inherits the normal Remote.DatabaseConnection; accepts a borrowed SQL database and population-bound LocalReadIdentity; rejects Memory; validates committed identity, then bootstraps read/push/invoke transports.
- ReadTransport (96), PushReadTransport (70), InvokeReadTransport (70): capture/strictly decode JSON, enforce bounds/cancellation and invoke the same protected database executors once.
It has no independent Session, cache or merge implementation. Removing it does not remove the 710-row shared workspace contract or the protected database read/mutation implementation. The production line saving is modest; the larger benefit is one fewer supported connection mode and provider-test axis.

Only two project files reference Allors.Workspace.Adapters.Local.csproj: Core/Workspace/Tests.Local/Workspace.Tests.Local.csproj and Core/Database/Server.Local.Tests/Server.Local.Tests.csproj. The solution lists the adapter and Local test project. Build Paths/Core targets, CI, API/documentation links and Remote's InternalsVisibleTo("Workspace.Tests.Local") also refer to the current layout. No production consumer project reference was found.

Local integration is 212 rows per provider, not all redundant source
The earlier full Local TRX and current source audit establish the 212-row expectation. Its decomposition is:
- 206 inherited common integration rows, already represented in each HTTP codec assembly (68 Pull facts plus 138 other inherited rows). Their Local execution can retire with the removed transport; shared source remains and still runs with both SQL providers through HTTP.
- Three Local-only SecurityTests facts: RefreshesKnownGrantWhenAnObjectIsSynchronized; RefreshesKnownRevocationWhenAnObjectIsSynchronized; RejectedExistingObjectPushReturnsAccessErrorAndRollsBack. HTTP Security wrappers have no corresponding declarations. These assert refreshed grant/revocation effects and rejected write rollback while unsaved Session edits remain. Preserve or explicitly reconcile their exact assertions through the retained HTTP/server test harness; do not delete them as duplicate inherited coverage.
- NormalLocalProfileLoginDrainsAllOwnedConnections (one row) tests Local fixture identity replacement and shared borrowed database ownership. Its Local-specific contract can retire with the Profile; comparable generic connection closure/HTTP Profile lifetime coverage remains.
- JsonApiPullDisposesItsTransaction(false/true) (two rows) is the paused legacy sink/transaction migration. Removing its workspace entrypoint makes that exact test obsolete, but its historical rollback intent needs an explicit server/executor-level disposition. Do not silently apply the previously unapproved replacement or count the failure as fixed by deletion.
This is 206 + 3 + 3 = 212, not 209 common rows. Retiring the common Local execution removes 412 repeated integration executions across two providers, while the other six Local-only rows need named treatment. Both HTTP codecs and SQL providers remain meaningful axes.

Server.Local.Tests must remain
Its name means direct server/database testing, not dependence on the removed workspace transport as a whole. The current source has ten Local/SystemText/Newtonsoft theories in PullRetryTests; only their ten Local argument rows would retire. The other twenty rows still exercise both codec adapters against the real SQL executors/controller harness.
A further 22 methods / 35 rows across four server test files currently depend only on the Local adapter branch (18 methods / 29 rows in PullRetryTests plus six rows in PullExtentTests, PushExistingObjectTests and InvokeTests). census.json lists the exact names. Some are exclusively Local construction/transport contract tests and may retire. Others protect behavior that remains supported: mapped relation identity/checkpoints after a committed save, fresh same-version permission changes, pending-query deletion, known commit versus failed refresh, bootstrap and drain ordering, unsaved edits/creation tracking, and atomic multi-method Invoke.
The existing CreateSessionConnectionAsync helper already supports SystemText/Newtonsoft over a test-local HttpMessageHandler, with real SQL executors and a read controller. It can retain direct SQL + workspace assertions without a live network server and without keeping the production Local adapter. For controlled-owner tests, adapt existing handler controls/recording to the retained remote connection, rather than recreating a production Local transport under a different name. Atomic Invoke's SQL persistence and workspace result assertions in ProtectedInvokeRealAtomicBatchReturnsOneOutcome are one example that must migrate, not vanish. The codec agent owns the deeper exact server disposition analysis.

What stays despite the word Local
ReadExecutor, PushReadExecutor and InvokeReadExecutor live in Allors.Database.Workspace.Json and are registered by Core's HTTP server. PostgreSQL/SQL Server adapters and all server authorization/transaction scope coverage stay. Identity and Entra authentication are independent of this workspace transport decision. No new endpoint removal or generic raw API retirement follows automatically.
